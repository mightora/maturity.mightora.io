1. Choose a starting point. Select New assessment. Start blank, choose one of six example frameworks, import a project, or explore the complete Power Platform example. Each choice adds a separate local assessment. Templates contain suggested criteria and empty scores. The complete example contains fictional evidence, scores and historical snapshots.
  2. Agree the scope. Name the assessment, identify the organisation, owner and date, and describe the systems or teams covered. Define a review date and version. Record any exclusions in the description so readers can interpret the scores.
  3. Define your hierarchy. Open Framework → Domains and capability groups. Add domains such as Governance or Engineering, optional groups such as Delivery practice, and individual capabilities. Use a capability’s Details control to move it between domains and groups, describe it and add assessment criteria. Domain and capability names can change without changing stable identifiers. Move up/down changes order. Duplicates receive new IDs.
  4. Check the maturity scale. The default levels are Initial, Developing, Defined, Managed and Optimised. Open Maturity levels and scoring to edit names, definitions, colours, guidance and evidence requirements, or use 2–10 levels. These are generic maturity definitions, not certification. Removing the last level changes live scores at that level to Not assessed after confirmation. Snapshots keep the original scale.
  5. Record current and target maturity. Review evidence against the level definitions and assessment scope. Select the current level that is consistently demonstrated and a realistic target. Use Not assessed for missing judgements and Not applicable for capabilities outside scope. Neither state becomes zero. In Details, record supporting evidence, rationale, recommendations, risks, owners and target dates. Criteria support your judgement and do not automatically calculate a score.
  6. Explore the results. Executive overview summarises scored maturity, attention flags, largest numeric gaps and domain means. Radar places capabilities around the edge and compares current, target and an optional previous snapshot using solid, dashed and dotted lines. Heatmap shows current, target or gap values alongside colour. Current vs target provides horizontal bars. Gap analysis can sort by business priority, numeric gap, weight or target date. History compares the overall assessment, a domain or an individual capability.
  7. Turn gaps into a plan. Gap = target minus current when both values are numeric. Negative gaps mean the current level exceeds the target. Business priority is an independent High / Medium / Low judgement. The highest numeric gap may not be the most urgent action. Review risks, dependencies, cost, ownership and deadlines. The attention flag counts a recorded risk, a positive high-priority gap, or a gap of at least two levels.
  8. Preserve a baseline. Select Capture snapshot before reassessing. A snapshot copies metadata, hierarchy, scores, criteria, theme and maturity definitions. Later changes leave it untouched. Open a snapshot as a new assessment to inspect or continue from it. History labels numeric scores against each original scale maximum. Changed scales, scope and capability definitions can make historical values less comparable.
  9. Export and share. Download complete JSON for a portable backup. PowerPoint exports native editable radar and bar charts, embedded Excel data, editable tables and text. In PowerPoint, select a chart → Chart Design → Edit Data to change its values. Word exports editable tables and text as the explicit alternative to an editable radar chart. Update its contents field in Word after opening. CSV exports capability rows, not a complete project. SVG and PNG export the current chart page. Print / save PDF includes the selected chart and complete filtered score table.
  10. Keep a reliable copy. Autosave and Save now store the workspace in this browser profile. Export JSON regularly because browser storage can be cleared and is not a secure or synchronised backup. Download the offline HTML or ZIP, open index.html by double-clicking, and import your JSON. The offline edition needs no server, CDNs, account or internet connection.
Scoring and weights explained

With weights disabled, the overall score is the arithmetic mean of numeric capability scores. With weights enabled, it is sum(score × weight) / sum(weights of scored capabilities). Set a positive weight, up to 1,000, in capability Details. The same rules apply within each domain. Current and target averages use their own numeric populations, so the average paired gap can differ from the difference between those averages. The charts and reports explain this methodology. Maturity is ordinal: averages are descriptive indicators and should always be read alongside evidence.

Imports structured editing and limits

JSON schema version 2 preserves the complete assessment. Legacy version 1 files from the earlier Mightora maturity tool are migrated with stable capability IDs. CSV should start from an exported file: retain id, domainId and groupId when editing. Use blank score cells for Not assessed and NA for Not applicable. Criteria use JSON within the quoted CSV criteria cell. CSV import keeps the active framework definitions and metadata and replaces its capability rows. An imported file creates a separate assessment. Structured source validation does not apply invalid data. Duplicate IDs, invalid scores, missing references and unsafe object keys are rejected. Spreadsheet formulas are prefixed with an apostrophe on CSV export.

Limits: 40 local assessments, 1,000 capabilities, 100 domains, 100 groups per domain, 100 criteria per capability, 30 snapshots, 2–10 maturity levels and 10 MB per imported project. Chart and editor pages keep larger assessments manageable. Reports include all capabilities. Very large reports may take longer to generate on mobile devices. Share payloads above 16,000 encoded characters use a downloadable JSON file instead.

Sharing and embedding

Share a read-only assessment, a summary, an embedded chart view or an explicitly editable copy. Read-only views never save to the local workspace. Editable copies remain temporary until Save as new local assessment is selected. A shared link is a snapshot: regenerate it to include future changes. A summary excludes evidence, recommendations, risks, owners, notes and snapshots, but still contains capability descriptions, criteria-free scores and framework definitions. Inspect all remaining content before sharing. Anyone with the link can decode it. Links have no access control or encryption. Use a JSON file and an approved secure channel for confidential assessments.

Keyboard and accessibility

Use Tab to move between labelled controls, Enter or Space to open a chart point, and Escape to close a dialog or navigation menu. Current and target series use labels and line styles as well as colour. Every chart has an accessible score table. Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z undo or redo when focus is outside a text field. Ctrl/Cmd+S saves locally. Native text fields retain their own editing shortcuts. Search and filters apply to charts and the editor. Reports always include the full assessment. Use chart zoom for detailed labels and the score table for long names.

Offline and privacy limitations

The standalone HTML bundles scripts, styles, images and export libraries and restricts outbound connections with Content Security Policy. Ordinary links open external websites only when followed. Local storage behavior for file URLs varies by browser and device, so always use JSON backups for portability. Opening a different HTML filename may use a different local storage area. iOS file previews may not execute a full application: use a desktop browser for the double-click offline edition. The online edition needs network access for shared branding assets and status badges. No assessment content is transmitted by the application.

The app targets WCAG 2.2 AA and includes keyboard and responsive checks. This is not an independent accessibility certification. Editable Office structures are tested automatically and representative files are rendered with LibreOffice when available. Microsoft Office rendering may differ. Custom fonts require installation on the recipient’s device. Read SECURITY.md and the verification report for the exact tested environment.
